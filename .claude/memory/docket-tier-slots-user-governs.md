When the user says a bundle has no Easy slot, take that as fact even if the saved task page reads "Question slots:
Hard 0/2 · Medium 0/3 · Easy 0/1" and "Still open on this set: Hard, Medium, Easy". Do not raise the page lines as an
open point, and do not plan on an Easy result being usable.

**Why:** user, 2026-10-10 (aq-02749), after I flagged those two capture lines twice: "although they say 'Still open on
this set: Hard, Medium, Easy', after checking difficulty, it blocks easy tier. So we must target at medium or hard."
The block shows only after a difficulty run, so a capture taken before one cannot contradict the user.

**How to apply:** set difficulty_target from the user's instruction; treat an "In band - Easy tier" result on such a
bundle as below target (no slot), as in [[docket-redesign-v2]]. Mention the slot lines only if the user asks which
tiers the page lists. My reading, not the user's words: the slot counter tracks accepted questions per set, while the
gate applies a separate availability rule.
