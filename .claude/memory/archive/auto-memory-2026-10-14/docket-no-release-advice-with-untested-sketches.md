When I hold a fair, screened Docket sketch that has not been quick-tested and the user still has quick tests left, I offer it for testing and give no release recommendation. I may say what the family measured on other bundles, as history, but not as a reason to skip the test.

**Why:** aq-03711, 2026-10-13. After two quick tests came back "too easy" (a rule-application question and a share-times-price sketch), I recommended release and described the two remaining sketches as date counts that "did not hold on sister bundles". The user tested them anyway and wrote "last one survived": a derived date under the draft's commencement clause plus the days to the end of the grace period. The same thing happened on aq-02933, where the user quick-tested a wording I had listed as untried after I had recommended release. Mine, not the user's words: the user's message was only the result; I read it as "test what is left before advising release".

**What the survivor turned out to be (same day):** the form's "One defensible answer" check failed it; both of its solvers had read the clause's starting date another way, and once the wording had one reading the quick test said "too easy". So the survival was an open reading, not difficulty. That does not change the rule above (test before advising), but a quick-test survival on a derived answer is not good news until "One defensible answer" has passed on the same wording, and I should say that when I report a survival.

**A second kind of false survival (aq-04045, 2026-10-13):** three wordings of one hook went to the quick test; the user reported "1, 3 too easy, 2 survived". The survivor needed exactly the steps the two failed wordings needed. I wrote it up and handed it over for a difficulty run, calling the survival "a screen only" without asking for a second quick test; the run came back "Too easy", low model 5 of 5. User's request afterwards: "plz check arrived verdicts by using your feedback skill and fix". Mine, not the user's words: when sibling wordings that need the same steps fail the quick test, a lone survivor is noise from one screen, so I ask for a second quick test of it before a write-up or a difficulty run.

**The same on a reworded sibling (aq-03736 q01, 2026-10-13):** the first wording had measured Easy at Low 1/5 with Easy closed. I reworded only the question (took the documents' own phrase out), the user reported "i10 survived", and I wrote it up as rev 1 and handed it over for a run with a caveat instead of asking for a second quick test or a different hook. Result: "Too easy", and the check had started at the Medium level ("Low — · Medium 5/6"): on a set with Easy full the solver to beat was the medium one, about which neither the quick test nor Run 1's Low count said anything. User's request afterwards: "plz check arrived verdicts by using your feedback skill and fix". Mine, not the user's words: a rewording of a wording that already measured below target is a sibling, not a new sketch, so the survivor rule above applies to it; and when Medium is the lowest open tier I audit the design against the medium solver before any run.

**How to apply:** in `D:\Projects\Projects\AfterQuery-Docket\10.8`, before writing "recommend release", list every sketch in the bundle's notes/ideas.md that is fair, screened and untested; if there is one and the page shows quick tests left, hand those over first. Recommend release only when every fair sketch has a result, or the user says they are out of tests.
