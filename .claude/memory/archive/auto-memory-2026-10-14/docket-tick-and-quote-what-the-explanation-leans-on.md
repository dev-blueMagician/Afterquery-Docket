Before handing over a Docket question, check each sentence of the step-by-step explanation: the document it leans on is ticked as necessary (role "Exclusion / condition source" with its reviewer note when the document only establishes a condition or rules out an alternative), there is a verbatim quote for it, and it describes the source exactly (a list's real size, which items are excluded and why). Do not leave a document unticked because the automated Document check would call it "not needed".

**Why:** aq-02749 q02 passed the difficulty check at Medium, was submitted, and came back from the platform reviewer on 2026-10-12 as a second send-back: "The gold answer (10) is correct and both traps land, so no change to the question or answer is needed. Please add Docs 3 and 4 as necessary documents, add the supporting quotes, and fix the wording in Steps 2, 4, 6 and 7." My explanation's Step 4 used two State lists (Docs 3 and 4) and a claim about other amendments with no tick and no quote; I had left them out because removing either document did not change the answer. Step 2 said a five-entry list "holds three more". Adding the ticks afterwards meant a new difficulty run on a question that had already passed. The first send-back never reached me; the user had resubmitted, and the reviewer wrote "None of the changes requested in the previous send-back were applied".

Open case where the form itself refuses the tick: aq-03170 q01, 2026-10-12. Two of three list members each came from one document; ticked as answer components they drew the blocking check "You marked documents 3, 13 as necessary, but the answer does not need them. Unmark them, or change the question so they are needed." I unticked them, kept their quotes, left the steps naming them, mentioned the reviewer risk in one line, and did not try the "Exclusion / condition source" role with its reviewer note. The question passed at Hard and was submitted that way. The reviewer returned it the next day (2026-10-13): "Question and gold are sound ... The only fix is tagging Docs 3 and 13, which each uniquely support an answer item" and "each changes the answer if removed, so both must be tagged". The untick cost a passed Hard result: restoring the ticks needs a new difficulty run. Mine, not the user's words: this is the thing most likely to come back on that question.

**How to apply:** in `D:\Projects\Projects\AfterQuery-Docket\10.8`, `tools/check_questions.py` warns when the reasoning names a Doc that is not ticked: treat it as blocking and settle the ticks before the first difficulty run. In the hand-over, name the sentences the user must keep word for word if they reword. When the user mentions a send-back or "revision requested", ask to see the panel before anything else. When the form refuses a tick for a document the steps name, stop before the difficulty run: try the tick with the exclusion role and note, or restructure so every named document carries a member the form accepts, and tell the user which ticks were refused and that reviewers have returned questions for it. Do not let a one-line caveat stand in for that.

What the late tick cost (aq-02749 q02, 2026-10-13): adding the two ticks the reviewer asked for made a new version, so the same question and answer were measured again and came back "Between levels" (easier solver 0 of 5, middle solver 4 of 5) where the first run had been Medium at 3 of 5. The earlier pass no longer counted, and the question had to be changed (a second parallel count) before it could be resubmitted. When reading a between-levels run, also read the right attempts for what they never used: five of six right attempts had skipped a second list, and the repair made that list count.

What the tick then needs on the form (aq-02749 q02, Run 3, 2026-10-13): with the two condition-source documents ticked, the difficulty check reached the answer without each of them and blocked Submit with "A marked document may not be needed", although the solver counts were in band. The reviewer note inside the Necessary documents panel did not prevent it. The page's route is a separate one-line note in the difficulty check (200 characters, cleared by any later edit to question, answer, reasoning or ticks), or naming the document as excluded in the reasoning; neither needs a new run. I had told the user the panel note was the route and they came back blocked. Put the ready-to-paste one-line note in the same hand-over as the tick, say it must be saved last, and announce the advisory rows a count answer in bare digits will draw ("Left-out items do not qualify" matches the digits in dates and page numbers; "Each description fits one thing" matches a phrase that is meant to span several documents).

Rule from the aq-03170 return: a document that is the only source of an answer item is always ticked. If a form check says the answer "does not need" it, do not untick: keep the tick, tell the user the check and the sole-source rule disagree, and have the check's row taken to the reviewer or an admin before any difficulty run is spent.

Outcome of that re-run (aq-03170, 2026-10-13): Medium, on a set where Medium was full, with the question unchanged; the platform's medium gate had changed between the two runs. So the marks are settled by the sole-source rule before the first difficulty run, because a tier already passed does not survive a change of ticks. When a returned question has to be run again, tell the user before the run that it is a new measurement and can land on another tier, and check the workspace's same-day notes on the gate first.
