After a Docket difficulty run lands below the stated tier, list what each low attempt cleared as well as where it missed. A repair that adds more gates of a kind the same capture shows cleared (a rule the documents state in a sentence, pointed at by a date, category or status word in the question) is the same family and must not go to a run. Also check that an added item does not use the same table row or passage as the one gate that did split the solvers.

**Why:** aq-03143, 2026-10-12. The user sent two captures in a row with "plz check arrived verdicts by using your feedback skill and improve" and then "... and fix". Run 1 (Easy, Low 2/5): all five low attempts cleared the stated escape rule; all three misses were in one table-against-rule cell. I read that correctly and still repaired by adding two more stated-rule items (a pre-commencement matter, an out-of-scope category). Run 2: Too easy, Low 5/5, and the cell that had split the solvers split none. The workspace note already said a solved family stays closed however many cells are added (step 4 of `docket-start-from-measured-misses.md` in `D:\\Projects\\Projects\\AfterQuery-Docket\\10.8\\.claude\\memory\\`); I did not apply it. My interpretation, not the user's words: the user expects each verdict read-out to change the next design, not only to be recorded.

**How to apply:** before handing a repaired sketch over for a quick test, write one line per added gate: what the solver must notice, and whether the last capture shows that kind of step cleared. If every added gate is of a cleared kind, say the hook has no repair and recommend release (see [[docket-user-states-open-tier]]) instead of spending a run. Related: [[docket-read-the-trace-before-naming-a-route]].

Do not add a step inside the passage that held.
