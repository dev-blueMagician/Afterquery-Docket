When the user says a Docket bundle has no slot for a tier (for example "there is no slot for Easy Tier for this bundle, we should target medium and high"), treat it as settled. Do not read the form's slots line against it, do not ask again, and do not offer a submission below the stated tier.

**Why:** On aq-02750 (2026-10-11) I got an Easy-tier pass on a Medium-target bundle, read the form's "Question slots Hard 0/2 · Medium 0/3 · Easy 0/1" as an open Easy slot, asked the user about it more than once and twice handed over an Easy-tier option. The user's reply: "I said q05 was too easy for quick test. And no easy slot left, so must be medium or high". The slots line counts accepted questions only; the form itself says a question in review holds its slot. My interpretation: the user also expects a plain test report ("too easy for quick test") to be taken at face value rather than queried.

**How to apply:** Record a pass below the stated tier accurately in the question file, then move straight to a different hook aimed at the stated tier, or say plainly that the bundle has none and recommend release.
