When a Docket question's gold has to be derived and a run or form check fails it, repair the wording that is open and nothing else. Do not add a cue to calculate (a percentage form, "on reported figures", "stated or implied"). Do not quote odds for a tier, and do not recommend releasing the bundle while the one-reading, no-cue wording of a hook whose counts were in band has not been run.

**Why:** aq-03120, 2026-10-11/12. After the Medium pass the user wrote: "submitted as medium tier. plz check arrived verdicts by using your feedback skill and upgrade your skill". One hook took seven versions, three difficulty runs, two form blocks and three failed quick tests. What each version measured:
- plain event inside the period, dollar answer, no cue: Easy, Low 1/5 (four low attempts gave the printed half-year figure, three after placing the period correctly);
- dating event named "first-half results": blocked twice by "One defensible answer" (both form solvers took the first half);
- percentage "on reported figures", and later "stated or implied": quick-test too easy both times;
- "its last completed financial half-year": Low 0/5, Medium 2/5 but "Answer not supported" (the high model read "half-year" as the interim reporting period);
- "the half of its financial year that last ended before" a footnote-dated event, no cue: Medium, Low 0/5, Medium 2/5.
Before that last run I told the user Easy was likelier ("roughly one in four" for Medium) and recommended release. Both were wrong, and the workspace already forbids tier odds. Mine, not the user's words: "upgrade your skill" means the lessons go into the skill files and tools, not only into notes.

**How to apply:**
- "Between levels" names two solvers. Read which, and repair toward the tier that is open, not toward the page's heading: "too hard for the medium model but too easy for the high model" with Medium open calls for the test to be one notch easier to meet (the documents' own kind of term, "any" for "a"), never a clause. The changed sentence goes back as a sketch for a quick test first. Workspace copy: WORKFLOW.md section 6, repair order 7.
- Before any repair that follows "Between levels", "Answer not supported" or a "One defensible answer" block, open this note in full and find the matching case; the index line is not the rule.
- Removing a cue word is not naming the scope. When "anywhere", "wherever" or an "including" clause comes out, the scope it carried goes back in as the name of the document or section set ("does X's response say"). `tools/check_questions.py` WARNs `cue` on "anywhere" and "wherever" too.
- The platform's "What to change" wording explains one run; it is not a tested design. Check it against the cases here before adopting it.
- Ask where the strongest solver stops by default (a complete-looking table) and whether the question's words give it a reason to read the rest.
- When a form block has to be cleared, write the least explicit wording that leaves one reading first (the evidence or the set named by its structure), and check which tier is open before choosing: an "Including" or "Counting" clause measured one tier easier on aq-03170. `tools/check_questions.py` now WARNs with code `cue`. A phrase that names the identifier deciding the set does the same without being a clause: "the three proposals under whose file numbers it was filed" was quick-test too easy on aq-03570 q02 (2026-10-13), written that way because the run before had ended "Answer not supported". A failed gate on one hook is no reason to start the next hook at its most explicit wording. The same hook then went: nothing named, blocked by "One defensible answer"; evidence named with aq-03170's opening ("Judging by all these letters together"), quick-test too easy. So that opening is not a general fix: it separated the solvers where the deciding fact sat in a different document from the lure, and not where both sat in one citation. Before reaching for it, check where the deciding fact sits relative to the lure. Under the three-solver medium gate (pages from 2026-10-13) it has measured Medium twice: aq-03950 q02, and aq-03170 q01 Run 3, the same text that was Hard the day before under the five-attempt gate. Both times the two recorded medium solvers missed twice and the solver whose text is not recorded was right twice. Do not plan a Hard result on this opening. On aq-03570 q05 (2026-10-13, a list of a joint letter's signers who later commented, two of them shown only in other commenters' letters) it measured "Too easy", Medium 5/9 with the check starting at Medium, and two of the right attempts quoted the opening as their reason to take cited commenters in: there it worked as a search cue. The repair sent back for a quick test keeps the scope and drops the cue ("do these letters show"), the aq-03169 move.
- At sketch time, write the set by its membership test ("letters that X signed") and check the draft for any clause beginning "Counting", "Including" or "Whether or not": each is a cue.
- Then test every member of the gold against that wording as the strongest solver will: an item the documents only report and do not include (a letter named in a footnote) is read as outside the set. Ask for that item directly, or pick a quantity that is the same with and without it (aq-03570 q01 rev 1).
- For a list or base with a member outside a complete-looking table, name the universe the member sits in ("whose ... total appears in the notice") before the first run. Do not tune a cue word, and do not tell the user a hook is finished, or that the next miss will end it, while that wording is untested.
- Check the workspace's measured recipes for the same shape before the first run (recipe 4 from aq-02673 had already described the first two results here).
- Before any test, search the bundle for each phrase naming the asked period or population; if a document prints it as a label for something else ("half-year results"), name the period by its structure. `python tools/docket_agent.py screen` in `D:\Projects\Projects\AfterQuery-Docket\10.8` now warns on the common period words.
- Never date a period by an event whose name carries another period's label.
- After a failed gate, read the strongest solver's every-document attempts first ([[docket-read-the-trace-before-naming-a-route]]). Same reading as the weaker misses means the term is open: one reading, no other change.
- To move a fair wording from Low 1/5 to Low 0/5, lengthen the step that places the period (an event dated after it, date in a footnote), not the arithmetic or the answer form ([[docket-repair-must-not-add-solved-family]]).
- Ask the user to look at "One defensible answer" before a difficulty run on a derived gold.
- Report the measured result and the next action; leave odds out ([[docket-user-states-open-tier]]).
