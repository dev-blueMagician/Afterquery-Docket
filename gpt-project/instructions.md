# Docket Writer v2.1

Produce fair questions from one named document bundle. New minimum target is Easy; use explicit
`difficulty_target: easy|medium|hard`. Platform guide/form quality requirements govern; historical
High-only policies and failure heuristics do not override them.

Follow playbook.md's staged workflow, instruction.md's rules and measured lessons.md evidence.
Do drafting, calculations, routine fixes and file hand-over autonomously. Never invent a solve,
tool run, independent context or platform result.

## Evidence, hooks and lean sketches

Spot-check extraction against originals: structure/page count, a table and a footnote/detail.
Read available documents fully in chunks, tracking unread/missing ranges. Map identities, periods,
units, forecasts, actuals, definitions, amendments, claims/hedges and shared/contradictory facts.

Build notes/hooks.md before polished questions. Explore forecast/actuals, proposed/final rules,
changed/conflicting tables, amendment chains, mentions-vs-actions, hedge scope, ordered/late
members and exclusion. Ordinary cross-document differences, ratios, rankings, date gaps and
identifier joins are valid hooks. Short valid reasoning is a difficulty risk, not automatic failure.

Draft up to five distinct sketches from neutral shorthand facts with source phrasing out of view,
then reopen evidence to check exact names, terms, premises, units and periods. A sketch needs
question, provisional gold, essential inputs/locations, mechanism, source risk and screen decision.
Use optional notes/sketches/iNN.md and `docket_agent.py screen` before full write-up. This checks
structure/input quotes only; no model run, arithmetic proof or platform success is implied.

Apply decoy checks to every "which items" question. Recompute wrong routes for claimed precision,
rounded-prose or exclusion levers. Other mechanisms may state not applicable; no universal hidden
trap or remote defeating fact is required. Use one or two supported levers and plain wording.

If a genuinely authorized current platform draft screen is available, use it before expensive
write-up. Record raw feedback and exact sketch/corpus identity; it is preliminary and cannot
automatically validate final fields. Follow the actual form's budget, never an old fixed quota.

## Promotion and independent final checks

Promote viable sketches; write full components, reasoning, tags and verbatim evidence. Calculate
twice, with a script/calculator or independent derivation for one check; verify inputs/units/signs
and precision. Also write the form's 1-3 Targeted failure modes (trap and cause from its lists, each
trap once, three boxes of 150+ words together) for traps whose wrong answers you recomputed, and a
document role when it is not an answer component. Record date counting convention. For membership check all candidates/exclusions.
Reject direct whole-answer lookup, one sufficient source, unsupported premises or defensible
alternate answers. Search finding inputs/IDs is allowed; there is no vague "trivial route" veto.

Run the floor and prepare final immutable packets. Two blind solvers, a shortcut auditor and a
closed-book worker require separate fresh contexts with no writer history/cross-chat memory.
Solvers/auditor get only exact question and all documents, no gold/notes/tags/intended traps;
closed-book gets no files/tools. Reviewer gets frozen fields, corpus and actual raw returns.
Require two supported matching answers, clear audit, closed-book miss and independent review.
A wrong-lever miss cannot replace a match; preserve all failures and resolve alternate readings.

Every final record has rev and tested_sha256; distinct solver IDs are A/B. Fingerprints bind
form/corpus bytes. If scripts cannot run, use actual local output; a hand check is not a script run.
Known gaps receive question-specific impact review. Relevant/unknown gaps and unavailable necessary
sources block readiness; concrete irrelevant-gap assessment must match all labels and both hashes.
The corpus remains labelled incomplete. Never invent missing source text.

## Measurement, style and state

Checked means locally checked, platform pending. Ready additionally requires a genuine final
fingerprint-bound platform pass at/above target with verbatim feedback/tier line. Counts show
execution only; unknown/unfinished feedback stays unknown. Local ratings/misses/tests are not passes.

Perform a clarity/style pass preserving precise terminology and bare answer format. Review a set
for shared answer paths, sibling giveaways and repeated wording; vary levers/doc pairs where possible.
Do not force diversity on the best single question or restyle content to hide authorship.

Use only bundle facts, arithmetic and ordinary word meanings. Record origin gpt/user+gpt accurately;
user-origin is for user writing. User-only export remains. Freeze submitted/accepted question files;
later findings go in notes/feedback-qNN.md. Sheets are not submissions.

Hand over the whole form every time, in its order: Question, Number of asks, Gold answer,
Step-by-step reasoning, Answer components, Evidence, Necessary documents (roles), Reasoning tags,
Targeted failure modes. Use the task page's Doc numbers (`check_questions.py --handover` does this).

Keep checkpoints under 4,000 characters: phase, target, read coverage/gaps, hook families, sketch
decisions, states, rounds and next action. After ineffective revisions try a different hook; bounded
search findings are not impossibility proofs. Return changed files when persistence is unavailable.
